# 元铸工坊 SOSOFAST · 技术验证路线

> © MiaoYu · 2026-09-09 · 定位声明：**技术验证期，商业化后置**
> 决策背景：技术专家评审指出核心难题（企业私有知识进 AI 的 ontology 级挑战 + 商业模式死区）与 Palantir 范式对照后，用户拍板——先验证技术假设，商业价值留待证据更厚时再决。
> 《项目介绍书》v3.7 与《内部备忘》转为存档（不删，监视清单继续生效）。
>
> **v2（2026-09-09 晚）**：吸收《Palantir范式学习报告》——知识沉淀层从"schema 文档"升级为**轻量本体**（对象+关系+动作，MCP 原生暴露）；领域模板标准升级为**四段式**（对象模型+动作库+工作流+评测集）；可胜利区间收窄至"中等关键度、知识密集型工作流"。

---

## 一、技术验证期的总目标

**用最小成本回答一个根本问题：元铸工坊的核心假设是否在产品形态下成立。**

五个字的检验标准：可复现、可迁移、可自助。

---

## 二、待验证假设清单（H1-H6）

| # | 假设 | 现有证据（项目形态） | 验证方式（产品形态） | 通过标准 |
|---|------|---------------------|---------------------|----------|
| H1 | **双输入工坊可产品化合并**：专家显性开发与对话学习两条线在同一平台并存，且产出符合四段式模板标准（对象模型+动作库+工作流+评测集） | 两条线各有独立实证（AIQA 走专家线、某企业协同项目 走对话学习线）但从未合并 | v0.1 平台同时承载两条输入线 | 一个真实用户分别用两条线各产出 ≥1 条**四段式合格**的可运行工作流 |
| H2 | **非技术者可用（鸿沟）**：无技术背景的业务人员无指导即可使用 | 无（专家代劳模式） | 找 1 名非技术同事，只给入口不给培训 | 30 分钟内独立完成一次真实任务，中途求助 ≤2 次 |
| H3 | **跨域泛化**：元流程可复刻第二个领域（供应链——创始人主场），按四段式标准（含该域的对象建模与动作库设计——这是轻量本体路线的首次实战） | 无（QA 域是唯一工件，且未按四段式） | 用元流程全流程复刻供应链的一个真实模块 | 产出**四段式合格**的领域工作流（对象模型+动作库+工作流+评测集）+ 全程记录（对专家"证据错位"批评的正面回应） |
| H4 | **对话学习的真实边界**：它承载企业适配层到什么程度 | 某企业协同项目 三级闭环（协同层有效） | 在 H1 平台上做边界试验：标记每条学习产物属于"协同层/流程层/领域知识层" | 输出诚实的边界地图：哪些能学、哪些学不会必须专家线补 |
| H5 | **域复刻成本**：第二领域四段式复刻 ≤3 人周（对象建模增加约 50% 工作量后的诚实预算；三层复用结构的量化验证） | 无 | H3 执行时实测计时 | 分层计时报告：内核复用/模板复用（含对象建模）/适配新建的真实占比 |
| H6 | **底座无关性**：方法论资产不绑死执行底座 | 架构原则（无实测） | 换底座演练：同一工作流在第二个执行底座上跑通 | 切换成本 ≤1 天，工作流资产零改动或仅改适配层 |
| H7 | **轻量本体可低成本落地**（Palantir 启发新增）：对象+关系+动作+staged writes+MCP 暴露，用 Postgres/SQLite 级实现即可支撑运行层 | 无（架构决策） | v0.1 知识层按轻量本体实现：对象/动作 schema 定义→MCP 工具化→AI 产出经 staged writes 人审落库 | AI agent 能通过 MCP 查询对象并执行 staged 动作；人审-落库-撤销链路全通；实现 ≤2 周 |

**优先级依据**：H1/H2/H7 是 v0.1 的三根柱（双输入产品化 + 鸿沟 + 轻量本体落地——Palantir 范式的最小验证）；H3/H5 回应"证据错位"批评（用供应链四段式实证把路线 A 的门票打出来）；H4 摸清对话学习的诚实边界（防止再次超载表述）；H6 验证架构承诺。**可胜利区间**（Palantir 学习后收窄）：中等关键度、知识密集型工作流（QA/审核/知识管理/流程自动化/内容生产）——不碰最高关键度实时决策与数据中台。

## 三、验证路线（依赖顺序）

```
阶段一（v0.1 平台）          阶段二（第二域）           阶段三（边界与底座）
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ 最小平台：        │   │ 供应链域复刻：    │   │ 对话学习边界试验   │
│ 双输入工坊 +     │──►│ 元流程全流程      │──►│ （H4）            │
│ 知识沉淀 + 运行  │   │ （H3）+ 计时     │   │ 底座切换演练       │
│ 自有 3 机网格    │   │ （H5）           │   │ （H6）            │
│ 验证：H1 + H2    │   │                  │   │                  │
└──────────────────┘   └──────────────────┘   └──────────────────┘
     4-6 周                   2-3 周                  2 周
```

**起步动作（不等平台）**：
- H3 的元流程部分立即可启——供应链域的需求挖掘→方案设计不依赖 v0.1 代码，按六环节流水线走（这本身就是练手）；对象建模（四段式之①②）在方案设计阶段同步产出
- H7 的本体 schema 设计可与 v0.1 spec 同步——先设计对象/动作 schema 语言（可参考《Palantir范式学习报告》4.1 节吸收清单）

## 五、出口条件（何时重新评估商业化）

**重启商业评估的信号**（满足任一）：
- H1-H5 全部通过 → 拿着"路线 B 的证据 + 路线 A 的门票"重新校准定位
- 验证期间出现外部信号：监视清单触发（distilly/aily 起量）或真实客户主动找上门

**调整方向的信号**：
- H2 连续两轮不过 → 鸿沟是结构性障碍，收缩为"专家服务+工具"模式
- H3 成本远超预期 → 跨域泛化叙事降级，聚焦单域深耕

**商业化挂起项清单**（重启时激活）：BP v3.7、内部备忘、商标注册、LICENSE 选型（AGPL/SSPL）——LICENSE 建议验证期就加（开源仓不该裸奔，与商业化无关）。

## 六、本路线的检验纪律

- 每个假设的验证产物：证据文件 + 过/不过结论 + 失败分析（继承"没有证据=没完成"）
- H3 全程按六环节流水线走（需求双视角→方案→TDD→双通道审查→实证）——**验证期本身就是元流程的持续练手**
- 路线文档随认知深化迭代（版本号管理，与 BP 同习惯）
