# 知乎回答 C9 —— Token 消耗优化（空题首发）

**问题**：AI Coding时如何有效减少Token消耗？

---

用 AI 编程快一年，token 账单从肉疼到可控，我的经验浓缩下来就一句话：**token 大头从来不是"写代码"，是"AI 读上下文"和"跑偏了重来"。**对症下药，六条。

## 1. 新会话是免费的，长会话是奢侈的

最常见的浪费：一个会话从早上聊到晚上，任务换了五个，AI 还拖着你上午的全部记忆跑——每轮请求都把几万 token 的旧上下文重新计费一遍。

**任务边界到了就开新会话。**"这个 bug 修完了吗？修完，新话题新开。"会话切换的人工成本几乎为零，token 节省是指数级的。

## 2. 喂文件要精准，不要"你自己去看"

两类极端都费钱：一是把整个代码库都给它（上下文爆炸）；二是只说"报错了你看看"（它自己满库找，读的比你还多）。

正确姿势：**直接给相关文件路径**。"问题大概在 service 层，这三个文件是相关的"——三句话，省掉它二十次工具调用的来回读。

## 3. 让它先出计划，批了再动手

大任务直接说"做完它"，AI 容易方向跑偏，跑偏的产物就是纯浪费的 token。

改成两段式：**"先给我方案，不要写代码"**——方案几十行 token，你扫一眼纠偏；批准后再放全量输出。跑偏成本从"重写一千行"降到"重写十行方案"。

## 4. 要 diff，不要全文重写

AI 有个坏习惯：改一个函数，把整个文件重新输出一遍。300 行的文件改 3 行，它愿意给你吐 300 行。

明确说：**"只给我修改的部分（diff/片段），不要输出整个文件。"**输出 token 是最贵的 token，这一条立竿见影。

## 5. 稳定规则沉到配置，别在对话里重复

你的编码规范、项目约定、禁区清单——如果每次都在对话里说一遍，就是每次都重新计费。

把它们写进 AI 工具的规则文件（CLAUDE.md / rules 这类，每个会话自动加载）。规则文件通常能命中提示缓存，**重复内容走缓存的价格远低于重新输入**，而且你不用再打字。

## 6. 简单活别用贵枪法

"这段日志什么意思""这个正则帮我写一下"——这种问题用最轻的方式问（普通对话/小模型），别开重型 agent 会话。工具的分寸感也是省钱：**杀鸡的刀和杀牛的刀分开买。**

---

最后说个反直觉的：**该花的 token 别省。**让 AI 多读一个相关文件、多跑一遍测试，这些"浪费"能挡住后面改 bug 的十倍消耗。省 token 的正确目标是砍掉"无效消耗"（重复上下文、跑偏重来、全文重写），不是砍掉"质量投入"。

一句话：**管住输入（上下文）、管住输出（diff 化）、管住重来（先方案后执行）**——这三管住，账单砍一半不奇怪。
