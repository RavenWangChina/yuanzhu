## 1. 目标与范围

**v0.1 验证三根柱**（《技术验证路线》H1/H2/H7）：

| 柱 | 验证什么 | 通过标准 |
|----|----------|----------|
| H1 双输入工坊 | 专家显性开发与对话学习两线在同一平台产出四段式合格模板 | 真实用户各用两线产出 ≥1 条可运行工作流 |
| H2 非技术者可用 | 无指导 30 分钟完成真实任务 | 求助 ≤2 次 |
| H7 轻量本体 | 对象+关系+动作+staged writes+MCP 暴露低成本落地 | agent 经 MCP 查对象/执行 staged 动作/人审-落库-撤销全通；实现 ≤2 周 |

**v0.1 做**：中控最小服务（本体层+模板库+任务分发+模型网关）、边缘代理（dsh-edge）、对话学习采集模块（企微一路）、Web 控制台（4 页）、首发测试工作流（AIQA 内容四段式化）。

**双部署形态**（ADR-011）：v0.1 以**单机模式（all-in-one）为第一验证形态**——dogfood 与 H2 真人测试直接装个人电脑，门槛最低；企业模式（server+edge）在同代码库启用，自有 3 机网格验证。模块化单体是硬约束：单机打包不许分叉代码。

**v0.1 不做**（明确出界）：市场分发协作（多用户上架/分成）、进化引擎自动化（只留数据埋点）、飞书/钉钉适配（只做企微）、私有化推理（local-vllm 留类型）、资产交易、移动端。

**自有 3 机网格 dogfood**（企业模式）：腾讯轻量（中控）+ 办公电脑 A（边缘+日常使用）+ 办公电脑 B 或某智能硬件企业机（边缘，验证远端注册）。**单机模式 dogfood**：办公电脑 A 本地 all-in-one（日常真实使用）。

       │ REST/WSS（Tailscale）         │ OpenAI 兼容

│ 边缘节点 A   │ │ 边缘节点 B│ │ DSH 执行    │ │ 模型   │

## 3. 组件设计

### 3.1 本体层（H7 核心，新建）

**Schema 定义**（领域无关的元模型，存 SQLite）：

```sql
-- 对象类型与实例
CREATE TABLE object_type (id, domain, name, title_key, description, schema_json, created_at);
CREATE TABLE object       (id, type_id, properties_json, title, created_by, created_at, updated_at);
-- 链接（关系实例）
CREATE TABLE link_type (id, domain, name, source_type_id, target_type_id, cardinality);
CREATE TABLE link      (id, type_id, source_id, target_id, metadata_json);
-- 动作类型与执行
CREATE TABLE action_type (
  id, domain, name,
  params_schema_json,          -- 参数 JSON Schema
  submission_criteria_json,    -- 运行时校验（如 status=Open 才可改优先级）
  side_effects_json,           -- [{type:webhook|notify, ...}]
  autonomy_level INTEGER,      -- 自主性 L1-L5（ADR-006：读高写低）
  requires_staging BOOLEAN,    -- 默认 TRUE
  description_for_agent TEXT   -- agent 工具描述（Palantir Agent tool description）
);
CREATE TABLE action_exec (id, action_type_id, params_json, status, staged_by, staged_at,
                          reviewed_by, reviewed_at, applied_at, reverted_at, exec_log_json);
```

**Staged writes 流**：agent/边缘调用动作 → `action_exec(status=staged)` → 审批人看 Web 控制台待审页（带上下文：谁/为什么/影响哪些对象）→ 批准则原子应用（对象/链接变更+副作用触发）→ 打回则标注理由；已应用动作可 revert（补偿事务，幂等键防重）。

**MCP 暴露**：中控内置一个 MCP server（FastAPI 挂 `/mcp` 端点，Streamable HTTP）：
- 对象类型 `exposed=true` 时自动生成查询工具（按 agent 身份过滤可见属性子集）
- 动作类型自动生成执行工具（描述用 `description_for_agent`；requires_staging 的动作生成"staged 执行"语义，工具返回 staged_id+待审状态）
- 参考 ObjectStack 的暴露标记设计；外部 agent（Claude Code/DSH）把中控 MCP 加进配置即可用

**约束与校验两层**（DMLA）：MCP 工具 JSON Schema 管格式；submission_criteria 管语义。

### 3.2 模板库（四段式标准）

```
template/
├── manifest.yaml        # 名称/版本/域/依赖/硬化清单状态
├── ontology/            # ① 对象模型：对象类型+链接类型定义（DSL：YAML 声明 → 本体层注册）
│   ├── object-types.yaml
│   └── link-types.yaml
├── actions/             # ② 动作库：动作类型定义（同 DSL）
│   └── *.yaml
├── workflows/           # ③ 工作流：编排（步骤引用动作与 AI 步骤）
│   └── *.yaml           # 步骤类型：action_step（引用动作库）| ai_step（提示词+模型+输入输出绑定）
│                        #                | transform_step（确定性转换，Golden Hammer 反模式对照）
└── evals/               # ④ 评测集：用例+预期（发布验收=硬化清单）
    └── cases.yaml
```

- 模板上传（zip 或 git 引用）→ 解析 DSL → 注册到本体层（对象/链接/动作类型 upsert，带版本）→ evals 可执行
- **AIQA 首发模板**：把 AIQA 的 qa-knowledge 体系四段式化——对象（Module/TestCase/Bug/Report/Evidence）+ 动作（CreateBug/ResolveBug/LinkEvidence/RegisterModule…）+ 工作流（考古/双用例/执行/报告的编排）+ 评测集
- **提示词分区**（ADR-008）：ai_step 提示词 = 稳定前缀（角色+规则，缓存友好）+ 可变段（任务参数）

### 3.3 对话学习采集（H1 第二输入线，v0.1 只做企微一路）

- 企微群机器人回调（或会话存档 API，视用户权限）→ 中控接收原始消息流 → **模式提炼 job**（调模型网关：从近 N 条对话提炼"高频工作模式候选"——谁经常要什么、什么请求反复出现、什么流程被重复描述）→ 产出 = **工作流候选草案**（staged 状态进模板库草稿区，人审后可四段式化）
- v0.1 诚实边界：提炼结果标注"协同层"（预期）；领域深层知识不指望从对话学（H4 验证时细化边界地图）
- 合规：只处理已授权群；消息原文不落库（只落提炼产物与统计），或按企业配置保留期限

### 3.4 任务编排与边缘代理（ADR-003 原样，概述）

- 状态机：pending→dispatched→running→done/failed（+cancelled）；节点 pull 模式（边缘主动拉，避免中控推到 NAT 后面）
- dsh-edge 四职责不变：注册/心跳 60s/执行（调本机 dsh headless profile）/用量上报
- 容错（ADR-008）：梯度超时三层、指数退避+抖动、降级兜底必须附上下文交人（DMLA："兜底交人工不带上下文=二次浪费"）

### 3.5 Web 控制台（Vue3，4 页）

| 页 | 内容 |
|----|------|
| 节点拓扑 | 节点列表/在线状态/能力标签/资源水位 |
| 模板市场（内部版） | 已装模板列表/版本/evals 状态/草稿区（对话学习候选在此人审） |
| 待审中心 | staged 动作审批（带完整上下文）/工作流候选审批 |
| 用量与审计 | 模型调用量/费用/操作日志 |

非技术者路径（H2 验证场景）：业务同事打开「待审中心」审 AI 提取的工作流候选，或从模板市场点「使用」触发任务——全程不碰代码不碰命令行。

## 4. 关键流程（三条主线的端到端）

**专家线（H1-a）**：管理员上传 AIQA 四段式模板 → 解析注册 → 分发到边缘 → 业务同事在控制台/IM 触发任务 → 边缘 dsh 执行工作流（ai_step 调模型网关，action_step 走 staged）→ 待审中心审动作 → 产出对象入本体 → 审计留痕。

**对话学习线（H1-b）**：企微群消息流 → 模式提炼 job → 工作流候选（草稿区）→ 管理员人审四段式化 → 上架 → 同专家线。

**MCP 外部 agent 线（H7）**：Claude Code（用户本机）把中控 `/mcp` 加入配置 → 直接查询本体对象（如"列出所有未解决 Bug"）→ 执行 staged 动作 → 待审中心审批闭环。

## 5. 测试策略

- **TDD**：本体层（schema DSL 解析/staged 状态机/MCP 工具生成）+ 编排（状态机/超时/降级）+ 模板库（四段式校验/evals 执行器）全覆盖 pytest

- **H2 特别设计**：找一位非技术同事，只发一个控制台链接，观察完成"审批一个 staged 动作+触发一个模板任务"的全过程，录屏+求助计数
- 首发模板（AIQA 四段式）的 evals 本身就是平台的第一批真实用户

## 6. 里程碑（v0.1 内部，TDD 顺序）
