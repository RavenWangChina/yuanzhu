## 根因分析

**Bug 2-4 共同根因**：forge prompt 中 query_step 的 schema 说明不完整——只说"query_step（查对象）"但没给字段级 JSON 示例。AI 生成了"合理猜测"的错误 schema。

## 修复建议（0.1.5）

1. **forge prompt 补全三步类型的完整字段 schema**（object_type/filter/output for query_step；action/prompt_prefix/prompt_var/model/output for ai_step；action/params for action_step）
2. **引擎容错**：query_step 缺 object_type 时给友好 400 而非 500
3. **evals 补充**：forge 产物运行前先跑一遍 dry-run（每步类型校验）

## 核心价值验证

```
用户对话（4 条周报类问题）
  → AI 自动发现模式（"至少 4 次询问…典型的例行公事模式"）
  → 建议条出现（一键操作）
  → forge 铸出完整四段式模板（含对象/动作/工作流/评测 2 条）
  → 模板市场上架
  → 点「使用」填参数运行
```

**从对话到工作流的完整闭环真实跑通了**——只差最后一步运行时因 schema 缺字段 500（forge prompt 问题，不是架构问题）。这是产品最核心的差异化体验。
