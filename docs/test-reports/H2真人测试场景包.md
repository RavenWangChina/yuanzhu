## 四、通过判定

- ☐ **通过**：两项任务独立完成（或求助 ≤2 次）且 ≤30 分钟
- ☐ **不过**：记录失败模式（卡在哪一步、什么措辞看不懂），录入技术验证路线文档

## 五、不过时的处置（spec 风险预案）

> H2 连续两轮不过 → 鸿沟是结构性障碍，收缩为"专家服务+工具"模式

第一轮不过的修复输入：
- 卡点截图 → Web 控制台改进清单（已知 4 条视觉打磨项见里程碑 5 简报）
- 看不懂的措辞 → 文案修订（如"staged 动作"→"AI 提交的修改"）
- 流程迷路 → 导航/引导改进
