# 知乎回答 2 草稿 —— vibe coding 工业级量化框架

**问题**：能不能通过 vibe coding，完成一个工业级的量化交易框架？
**定位**：执行验证层（与上篇"决策权归属"形成系列）· 只谈代码工程不谈交易

---

能，但先把账算清楚：**"工业级"三个字，90% 的成本不在写代码，在验证。而 vibe coding 恰恰把写代码的成本打到了接近零——于是验证成了唯一的瓶颈。**

我每天的活就是用 AI 写工业级软件（一个 AI 工具项目，161 个自动化测试）。一年下来最大的体会：AI 写代码快，不会让你交付快。你交付的速度取决于你**敢不敢信它写的**。代码产能翻了十倍，你 review 的带宽一倍没涨——这个剪刀差才是 vibe coding 工业化的真问题。

量化框架把这个矛盾放得最大，因为它有个别的领域没有的特性：**回测会给你打分**。这个特性很阴。

## AI 写量化代码的三个坑，全是"跑分漂亮"型的

**一、前视偏差（lookahead bias）。**AI 会一本正经写出"用当天收盘价决定当天买入"的回测——用未来数据算信号，跑分当然漂亮。它不是故意骗你，它对"时间"没有概念，训练语料里的量化代码本来就不分好坏，它只是把最常见的错误模式流利地复述给你。不专门测，你根本看不出来。

**二、过拟合，而且它特别乐意。**AI 是被训练来迎合你的。你说"这个策略好像不太行"，它就调参数、加过滤、叠指标，直到回测曲线完美——每一步都"有道理"，合起来就是把噪声拟合成了圣杯。回测好到不真实的策略，先怀疑 bug 和过拟合，再怀疑自己发现了 alpha。

**三、没有成本概念。**这个问题下已经有人踩过：让它拉美股数据，直接最细粒度全量进内存。它不付账单，你付。

注意这三个坑的共同点：**每一个都会让回测结果看起来更好**。这就是为什么量化是 vibe coding 最危险的场景——错误的方向和赚钱的方向是同一个方向。

## 所以工业级的关键动作：把 AI 的产出从"代码"降级成"提议"

具体纪律，四条，全部可执行：

**1. TDD 反着用。**先写测试，再让 AI 实现。测试是标准，AI 是实现——这样你 review 的不是几千行代码（你 review 不动），是几十行测试（你 review 得动）。测试写错了标准就错了，所以测试自己写，这个不能外包。

**2. 回测的三重怀疑。**跑分太好，先查前视偏差（把信号时点打印出来对）；样本内完美，换时间段、换品种再跑；AI 解释得头头是道，记住它是在迎合你，不是在验证你。

**3. 写操作分级。**回测、模拟、实盘之间每一次跳变，人批准。AI 可以提议加仓、可以提议改参数，落盘之前停一下。这一下就是工业级和玩具的分界线。

**4. 给"AI 不能做什么"写测试。**听起来玄，我给你个实例：我们项目 161 个测试里，专门有一类测试在验证"AI 无法绕过审批"——每次有人（包括 AI）试图直接写库，系统必须拒绝并留痕。治理不靠自觉，靠测试用例钉死。

## 回到问题本身

能不能 vibe coding 出工业级量化框架？**代码层面完全能，而且很快。**真正的问题是：你愿不愿意把省下来的写代码时间，加倍花在验证上。工业级从来不是"写得好"，是"错了能知道"。

顺便说一句，验证 AI 的产出这事本身也可以让 AI 干——我们让 AI 自评、人审偏差，这一层做起来之后，吞吐量才真正上来。这又回到我一个小时前在另一个 AI 失控问题下写的那个说法：失控的本质不是 AI 太强，是系统的动作频率超过了你审核的频率。vibe coding 的工业化，就是把频率差管起来。
