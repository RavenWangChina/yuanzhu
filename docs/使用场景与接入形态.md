# 使用场景与接入形态

> 你第一次听说元铸工坊？从这里开始。
> 一句话：**按你们自己的工作习惯，把最佳实践变成可运行、可治理的 AI 工作流资产——AI 提议，人拍板。**

---

## 一、它是什么形态的产品？

一台独立运行的**引擎服务**（本体 + 模板 + 工作流 + 审批），三种使用界面：

```
                    ┌─────────────────────────┐
                    │   元铸工坊（引擎服务）    │
                    │  127.0.0.1:8600 常驻     │
                    │  本体层+模板库+工作流+审批│
                    └───┬──────┬──────┬──────┘
                        │      │      │
          人用 ─────────┘      │      └───────── agent 用
          Web 控制台           │              Claude Code / DSH
          （业务员工）         │              （MCP 协议接入）
                        开发者用
                        CLI（yuanzhu 命令）
```

- **单机模式**（个人/小团队）：一个本地进程 all-in-one，数据全本地
- **企业模式**：服务器中控 + 各电脑边缘节点（开发中）

## 二、三种用户的一天

### ① 业务员工（张三，QA）——只用 Web，不需要知道 AI 为何物

早上打开 `http://中控地址:8600`：

- **待审中心**有几条「AI 提交的修改」（昨晚 Claude 跑的考古用例、AI 写的测试日报）——看一眼，批准或拒绝（拒绝要写理由）
- 想跑点什么？**模板市场**点「使用」→ 填个标题 → 产出进待审中心等你确认

全程不碰命令行。这就是我们的设计标准：**非技术同事无指导 30 分钟完成真实任务**（求助 ≤2 次）。

### ② 开发者/专家用户（李四）——Claude Code + MCP

给 Claude Code 接上企业本体（一条命令）：

```bash
claude mcp add yuanzhu http://中控地址:8600/mcp
```

之后在 Claude Code 对话里说人话：

| 你说 | Claude 自动做的事 |
|------|------------------|
| "列出所有未解决的 Bug" | 调 `query_aiqa_bug`（它知道你们的 Bug 长什么样） |
| "给登录模块设计双用例" | 查本体避免重复 → 提交用例（**staged 等人审**） |
| "把支付回调那个提到 P0" | 提交 `execute_aiqa_changepriority`（staged） |

**Claude 获得了什么**：企业的记忆（本体——它不再失忆）+ 企业的治理（staged——它不能乱写）。
任何支持 MCP 的 agent 都能这样接入，不只 Claude。

### ③ 管理员/最佳实践作者（王五）

```bash
yuanzhu status && yuanzhu pending          # 巡检
yuanzhu templates && yuanzhu approve 3     # 审批
yuanzhu import 群聊导出.txt --refine       # 对话学习：高频模式自动变候选
yuanzhu mcp tools                          # 看 agent 能用什么工具
```

- 注册领域模板（四段式：对象模型/动作库/工作流/评测集）
- 审对话学习候选上架（AI 提炼的工作流草案，人审四段式化）
- 用量与审计页看模型花费

## 三、核心概念（一分钟版）

| 概念 | 是什么 | 类比 |
|------|--------|------|
| **本体层** | 你们的业务对象（Bug/用例/报告…）+ 动作（受治理的写操作） | 业务世界的数字孪生 |
| **staged writes** | AI 的所有写操作先进待审区，人批准才生效 | AI 提议，人拍板 |
| **四段式模板** | 对象模型+动作库+工作流+评测集的领域最佳实践包 | 可安装的"专家经验" |
| **对话学习** | 从群聊记录提炼高频工作模式→工作流候选 | 企业习惯自动"铸"出来 |

## 四、快速开始

```bash
pip install yuanzhu
yuanzhu-server     # 打开 http://127.0.0.1:8600——首启自动带 3 个内置模板
```

模型接入零配置（自动读取 dsh 已配的 provider）；无 dsh 时用环境变量自定义任意 OpenAI 兼容端点（见 [ADR-014](架构决策记录.md)）。

**装完先问一个问题试试**（不用开发任何东西）：

```bash
yuanzhu run metaflow deep-answer --param question="你正在纠结的真实决策问题"
```

这是**元流程问答**：你的问题自动走六步流水线（澄清→双视角**并行**作答→独立审查→综合裁决→人审采纳），
产出带量化判断门槛的结构化答案——同模型裸问与流水线的[同题对垒实证](test-reports/metaflow-duel-2026-09-10/对比结论.md)。

其他内置模板：AIQA 测试工作流 / 会议追踪。没有想要的？输入框一句话铸造（见下节），
或 CLI `yuanzhu forge "你的描述"`——铸出的模板落在 `~/.yuanzhu/templates/forge/`。
（源码仓用户可跑 `server/seed_h2.py` 造演示数据）

## 四点五、没有你想要的模板？一句话铸造

模板市场顶部有个输入框——**用大白话描述你的日常工作，AI 直接铸成模板**：

> "我每天要收集各组的工作进展，汇总成一份日报"

AI 生成完整四段式（对象/动作/工作流/评测）→ 评测自动验证 → 全过即上架立即可用。
CLI 同款：`yuanzhu forge "你的描述"`。详见[模板开发指南](模板开发指南.md)。
