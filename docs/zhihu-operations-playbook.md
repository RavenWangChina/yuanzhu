## 三点五、工具边界（CLI vs 浏览器，2026-09-15 定稿）

| 场景 | 工具 | 命令/路径 |
|------|------|----------|
| 巡检数据（赞同/评论数） | CLI | `me contents --sort ts` |
| **我的回答/文章收到的评论** | CLI | `me comments --content-url <url> --order reverse`（秒查，替代浏览器翻评论区） |
| 选题挖掘 | CLI | `question recommend --query X`（多 query 轮）+ `hot` + `search zhihu` |

| **素材 RAG 检索** | CLI 知识库 | `knowledge search --query X --base-id 7685601558406478287`（⚠️ 必须 --base-id 显式指定，--scope personal 不含自传文件；素材库已上传 zhihu-material-bank.md） |
| 素材库更新 | CLI | 素材库 md 更新后 `knowledge upload --file <path>`（单文件，≤100MiB） |

| 知识沉淀 | CLI | `knowledge` + 元铸工坊 distill-insight |

## 三、风控条款（v1 裁决保留部分，永久有效）

- **同质化红线**：2019 年重复内容违规前科——每篇 ≥30% 一手增量（新案例/新数据/新角度），纯观点复述不发
- AI 辅助创作声明每篇必选（透明度是护城河也是防御）
- 脱敏红线：不提公司/天翼云/真实同事
- 不可逆动作（付费/绑号/删除）仍先问用户
- 若出现限流迹象（阅读量异常低），暂停排查而非加量硬发

**验证有效的打法**：
1. **差异化公式**：接住已有高赞观点→给出全场没有的视角（治理/验证）→金句收尾。每篇一个新概念锚点，17 篇形成互相引用的概念网
2. **评论区即流量池**：头部回答下"接住+翻新"式评论比自说自话有效
3. **选题三层漏斗**：CLI question recommend（垂直）+"为你推荐"（画像生效后自动匹配）+热榜扫描
4. **发布流水线**：直答观点地图（9.5s）→本地写作→单 evaluate 四合一发布（约 3 分钟/篇）

**踩坑与红线（实证）**：
1. **风控形态**：单日 15-16 篇后发布按钮静默失灵（无提示无报错），刷新无效，草稿自动保存；评论点赞不受限。**纪律：日发文上限 12 篇**
2. CLI me contents 的 LikeCount 延迟数小时，巡检以通知页为准
3. 定向回复子评论自动化困难（Dialog+排序+折叠嵌套），用 @提及 兜底
4. 编辑器三防：粘贴丢加粗/按钮需真实事件/搜索页只出联想词
