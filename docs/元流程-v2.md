## 总体结构：双环

```
外环·知识环（跨环节持续运转，v2 新增的一等公民）
  情景记忆 ──提炼──► 语义规则（可复用）──反哺──► 各环节输入
     │                                        ▲
     └────────── 软遗忘（过期降权）◄── 模式库 ◄─┘（历史失败模式）

内环·六环节（每环节一个治理门，全过才进下一环节）
  0 输入 ─► 1 需求挖掘 ─► 2 方案设计 ─► 3 执行 ─► 4 审查 ─► 5 验证 ─► 6 硬化交付
```

## 环节 0：输入（v2 新增——双源输入）

| 源 | 形态 | 纪律 |
|----|------|------|
| 人工指令 | 用户直接提出 | 不变 |
| **对话学习候选** | 从工作痕迹（IM 对话/历史产出/日志）提炼的任务/工作流候选 | **staged 人审后才进入环节 1**（AI 提炼≠需求，标注"协同层"预期） |

## 环节 1：需求挖掘

- **保留 v1**：双视角对抗（superpowers 工程 × product-management 业务），分歧列对照表给用户裁决，不自行取舍
- **v2 新增·四补全核验**（DMLA）：派任何 subagent 前明确交代四样怎么补——工具（给它什么工具）、检索（它要查什么）、记忆（它知道什么上下文）、自省（它怎么验证自己）。缺一样就不派
- **v2 新增·知识环输入**：挖需求前先查模式库（历史同类问题的失败模式）与语义规则库

## 环节 2：方案设计

- **保留 v1**：writing-plans 主稿 + 对抗审查（codex-skill 或对抗 subagent），逐条回应不糊弄
- **v2 新增·对象与动作建模**（Palantir）：方案必须包含①对象模型（实体+关系）②动作库（每个写操作：参数+校验+副作用）——即四段式模板的①②在方案期产出，执行期只是实现它们
- **v2 新增·自主性标注**（DMLA L1-L5）：方案里每个写操作声明等级——**读高写低**；写操作默认 staged 人审；连续 N 次 A/B 通过可逐级放行
- **v2 新增·反模式核验**：方案对照反模式清单（Kitchen Sink/God Object/Golden Hammer/System Silos——Golden Hammer 尤其：确定性转换不用 AI 步骤）

## 环节 3：执行

- **保留 v1**：TDD 红→绿→重构，失败先行；SDD 按任务派发，从对话共用运行逻辑（读 00-索引→只干职能内→产物落盘回传指针→不通信）
- **v2 新增·容错五件套**（DMLA）：
  - **梯度超时**：工具调用 30s / 推理 5min / 整任务 1h，超时截断上报而非挂死
  - **重试**：指数退避+抖动；确定性错误不重试
  - **降级兜底**：兜底路径必须存在；**交人工时必须附完整上下文**（不带上下文的兜底=二次浪费）
  - **检查点**：长任务阶段性落盘，恢复后共享上下文（"迟到者进会议室"问题）
  - **断路器**：同类失败连续 N 次熔断，防故障扩散
- **v2 新增·提示词分区**：AI 步骤的提示词=稳定前缀（角色+规则，缓存友好）+可变段（任务参数）——前缀缓存命中=成本数量级差异
- **v2 新增·从会话健康**：长时从任务带心跳与超时分级（STUCK 判定+≤2 次重派）

## 环节 4：审查

- **保留 v1**：双通道（pr-review-toolkit × coderabbit），都过才放行；意见按"先验证再改"处理
- **v2 新增·第三通道（按需）**：安全敏感变更加 semgrep/ZAP 类扫描；文档/配置变更加 schema 校验
- **v2 新增·反模式复审**：对照环节 2 的对象/动作设计审查实现是否走样

## 环节 5：验证

- **保留 v1**：证据先于结论——UI 截图实证、pytest 输出实证、没有证据=没完成
- **v2 新增·staged 核对**：本任务的所有写动作是否按声明的自主性等级执行了（该 staged 的是否 staged、该人审的是否人审）

## 环节 6：硬化交付（v1"提交"的升级）

- **保留 v1**：用户说提交才提交（不可逆动作检查点）
- **v2 新增·硬化清单**（Palantir FDE 五阶段之"硬化"，=PoC 与生产的分界）：
  - ✅ evals：本变更有测试且全绿（不只是"能跑"，是"被测"）
  - ✅ 审计：操作日志留痕（谁/何时/改了什么/证据路径）
  - ✅ 成本：模型调用计量（token/估费落账）
  三件全过=硬化完成，可交付；缺任一=回环节 3
- **v2 新增·副作用治理**：幂等键（重试返回缓存结果）+ 补偿事务（不可回滚的副作用用语义反操作中和，补偿本身幂等）
- **v2 新增·记忆提炼**（知识环的驱动点）：交付时强制回答两个问题——①本轮有什么情景记忆值得提炼成语义规则（"这次 X 坑，以后 Y"）？②有什么旧规则被本轮证伪（进软遗忘）？产出写入知识库/模式库

## 知识环（外环）运转规则

| 机制 | 规则 |
|------|------|
| **情景→语义提炼** | 每轮交付触发（环节 6）；提炼物=可复用规则，非事件流水账 |
| **反哺** | 环节 1/2 的必查输入（模式库+规则库）；不查就设计=重蹈覆辙 |
| **软遗忘** | 规则带时间戳与适用域；连续 N 轮未被引用或被证伪→降权标记（不硬删，可恢复） |
| **模式库** | 失败模式登记（同类问题第二次出现必须成模式）；模式的每次再现触发针对性动作 |
| **flaky 消化** | 时好时坏的用例/任务单独登记，隔离出主线，3 次取多数后定性 |

## 检查点体系（v2 统一）

| 级 | 触发 | 例子 |
|----|------|------|
| **人审（staged）** | 一切写动作（按自主性声明） | 代码提交前、模板上架、对外发送 |
| **裁决** | 分歧点/方案级取舍 | 双视角结论冲突、架构二选一 |
| **不可逆确认** | 无法用补偿事务中和的动作 | push/删除/外发 |

三层从细到粗：动作级（staged）→ 决策级（裁决）→ 不可逆级（确认）。

## 与 v1 的差异总表（工坊产品化时的变更清单）

| 项 | v1 | v2 |
|----|----|----|
| 输入 | 单源（人工） | 双源（+对话学习候选，staged 人审） |
| 方案 | 分步计划 | +对象/动作建模（四段式①②前移）+自主性标注 |
| 执行 | TDD/SDD | +容错五件套+提示词分区+从会话健康 |
| 审查 | 双通道 | +第三通道（按需）+反模式复审 |
| 验证 | 实证 | +staged 执行核对 |
| 提交 | 用户确认 | **硬化交付**（evals/审计/成本三件门）+幂等/补偿+记忆提炼 |
| 知识 | 隐式（CLAUDE.md 记环境事实） | **知识环显式化**（提炼/反哺/软遗忘/模式库/flaky） |
| 检查点 | 三类停顿 | 三级体系（动作/决策/不可逆），与 staged writes 对齐 |
