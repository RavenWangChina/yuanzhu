# v0.1.6 实施计划（推衍引擎——主动创造·主动挖掘·主动学习）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal**: 从被动响应转向主动推衍——基于三记忆系统交叉分析，推衍用户意图，交付超预期结果

**Architecture**: Letta 心跳模式 + Mem0 自动提取 + 三记忆系统理论
- **Episodic**（新增）：BehaviorLog 记录用户行为序列
- **Semantic**（已有）：Insight 知识库
- **Procedural**（已有）：Workflow/Template
- **心跳引擎**（新增）：定期交叉分析三系统 → 产出 Proposition（主动提议+交付物草稿）

**Tech Stack**: 复用全部现有基础——FastAPI/SQLAlchemy/GLM/本体层/staged writes

## 现有基础精确映射（不重复造轮子）

| 理论概念 | 已有实现 | v0.1.6 新增 |
|----------|---------|------------|
| Semantic Memory | Insight 对象 + distill-insight 工作流 + auto-distill | 无需新增（已完备） |
| Procedural Memory | 四段式模板 + forge + evals 守门 | 无需新增（已完备） |
| Episodic Memory | **无** | BehaviorLog ORM + 自动记录点 |
| Memory Consolidation | adopt 端点（标记+触发沉淀） | 无需新增 |
| Heartbeat | **无** | inference/run 端点（手动触发 → 后续定时） |
| Agent Self-Reflection | **无** | infer 步骤（deep-answer 第七步） |
| Memory Retrieval | query_step（结构化过滤） | 无需新增 |
| Proposition Delivery | forge（模板草稿） | Proposition 对象（通用提议容器） |

## 效果评估标准（关键——元流程环节 5 依据）

### 量化指标

| 指标 | 定义 | 目标 | 测量方法 |
|------|------|------|---------|
| **推衍命中率** | Proposition 被采纳的比例 | n≥30 时 ≥30% | adopted / total（metrics 加 days 参数+样本量输出） |
| **超预期感知率** | 用户标记"超出预期"的比例 | 暂不测（v0.1.6 不加 rating——T4 没有落地它的任务） | v0.2 加 rating 字段后再测 |
| **意图推衍准确度** | infer 建议的 expected_action 与后续 24h 内 BehaviorLog 匹配 | ≥50%（infer 输出结构化 `{advice_text, expected_action}`，expected_action 是 BehaviorLog action 枚举） | 自动比对 |
| **响应速度** | 心跳引擎单次分析耗时 | ≤60s | 引擎内计时（metrics 加 duration 字段） |

### 质性验证（dogfood）

1. **端到端场景测试**：真实使用 1 周 → 推衍引擎是否产出过"用户没想到但有价值"的提议
2. **对比测试**：同问题，有无 infer 步骤的答案对比——infer 版是否显著更好
3. **用户主观评价**：推衍建议的实用性 1-5 分

### 不做什么（边界）

- 不做实时流式推衍（用户打字时预测——v0.2+）
- 不做多用户协同推衍（企业模式的事）
- 不做全自动执行（推衍产出永远 staged 人审——核心治理不变）

### T2 意图推衍步骤（deep-answer infer）

**Files:**
- Modify: `server/src/yuanzhu/templates/metaflow/workflows/deep-answer.yaml`（加 infer 步 + 前置 behavior_step）
- Modify: `web/src/views/Chat.vue`（审查 C3：渲染 infer 输出"下一步推衍"块）
- Test: `server/tests/test_t2_infer.py`

**Interfaces:**
- Consumes: BehaviorLog（近 N 条）+ Insight（全部）+ 当前问题
- Produces: infer 步骤输出 = `infer_advice` 字段（附加到答案）

**infer 步骤设计**：
```yaml
- id: infer
  type: ai_step
  prompt_prefix: |
    你是意图推衍师。基于用户的当前问题、行为历史和知识库，推衍：
    1. 这个问题背后的深层意图（用户准备做什么，不只是表面问什么）
    2. 用户可能没想到但基于已有知识应该考虑的角度
    3. 超预期建议（比用户原本预期的更有价值的下一步）
    简洁输出，300 字以内。如果无法推衍出有价值的建议就输出空字符串。
  prompt_vars: ["params", "behavior", "insights"]
  # behavior 来自 behavior_step 的 output（审查 C1：不能凭空引用）
  model: glm-5.1
  output: infer_advice
```

**注意**（审查 C3）：infer 放在 verdict 之后、save 之前——`SaveAnswer` 的 content 引用 `$final`（verdict 输出），infer 的推衍建议要附加到 content（`content: $final + infer 输出拼接`）还是作为独立字段展示？计划决策：**独立字段展示**（不污染答案本体），Chat.vue details 区加 infer 块。

**Interfaces:**

- Produces: `Proposition` ORM（id/type/insight/advice/deliverable_draft_json/status/confidence）
- Produces: `POST /inference/run` → List[Proposition]

**Proposition 类型**：
```python
class PropositionType:
    WORKFLOW_SUGGESTION = "workflow_suggestion"   # "你该铸一个 X 工作流"（附 forge 草稿）
    KNOWLEDGE_GAP = "knowledge_gap"                    # "你有 X 洞见但缺 Y 关联"（附推衍洞见草稿）
    PATTERN_INSIGHT = "pattern_insight"            # "你的行为模式暗示..."（附分析报告草稿）
    PROCEDURAL_HINT = "procedural_hint"            # "你重复做了 X，试试已有工作流 Y"
```

**推衍 prompt 设计（提示词分区——稳定前缀+可变段）**：
```
稳定前缀：你是行为意图推衍师。基于用户的三记忆系统（行为/知识/技能），
交叉分析并产出主动提议...

可变段（审查 I3 体量约束——防 prompt 爆炸）：
- BehaviorLog：截最近 100 条
- Insight：只传 {takeaway, context}（不传完整对象）
- Template：只传 {name, description, workflow_count}（不传 workflows_json/evals_json）
- 偏好信号：只传 {preferred_types, dismissed_types} 摘要

输出：JSON 数组 [{type, insight, advice, deliverable_draft, confidence}, ...]
```

## 自主性标注

| 操作 | 等级 | 理由 |
|------|------|------|
| 行为记录 | L1（自动） | 日志写入无风险 |
| infer 步骤执行 | L1（自动） | 只产出建议文本不执行 |
| Proposition 创建 | L1（自动） | 只是提议容器 |
| **Proposition 采纳→执行交付物** | **L2（人审）** | 可能创建模板/洞见——staged |
| 偏好学习 | L1（自动） | 只是分析信号 |
