## ADR-001 总体架构：五环飞轮 × 双层通信 × 执行底座无关

- **五环飞轮**：①工坊（生产，双输入：专家显性开发+对话学习隐性提炼）→②市场（分发）→③运行（使用）→④沉淀（积累，轻量本体）→⑤进化（迭代，A/B+人审）
- **控制面/数据面分离**：控制面（任务/心跳/模板分发，走中控）；数据面（Agent 执行读本机文件、产出留本机或按需上传）——隐私边界"数据不出本机"
- **执行底座无关**（H6）：方法论资产不绑执行框架，DSH 为首选底座（pin 版本+适配层隔离）

## ADR-002 技术栈

| 组件 | 选型 | 备注 |
|------|------|------|
| 中控服务 | Python/FastAPI 单进程 + SQLite（v0.1）→ PostgreSQL 预留迁移 | 熟练栈+AI 协作验证过的组合 |
| Web 控制台 | Vite+Vue3，FastAPI 托管静态文件 | 与 某企业协同项目 同栈经验 |
| 边缘节点代理 | dsh 插件（TypeScript 薄层，命名 dsh-edge） | 蹭 DSH 插件市场分发；四职责刻意薄：注册/心跳/执行/用量上报 |
| 模型网关 | LiteLLM 集成（不自研） | OpenAI 兼容端点；私有化推理留 local-vllm 类型 |
| 知识层存储 | Postgres/SQLite | 轻量本体实现（见 ADR-004） |
| 组网 | Tailscale（REST/WSS over 虚拟网络）+ OpenSSH 运维备份 | 零公网暴露 |

## ADR-003 三组件边界（会话早期确认，模块级）

### 中控（FastAPI）
| 模块 | 职责 | 对外接口 |
|------|------|----------|
| 节点管理 | 注册/心跳 60s/在线状态/能力标签（OS/DSH/GPU） | POST /api/nodes/register、POST /api/nodes/{id}/heartbeat |
| 任务编排 | 创建→排队→按能力选节点→分发→状态机（pending→dispatched→running→done/failed） | POST /api/tasks、POST /api/nodes/{id}/tasks/pull |
| Agent 模板库 | 上传（zip/git 引用）→版本管理→分发 | POST /api/templates、GET /api/templates/{name}/{ver} |
| 模型网关 | 见下 | OpenAI 兼容 /v1/* |
| 权限与审计 | token 三级（admin/node/user）、操作日志全量落库 | 中间件，GET /api/audit |
| Web 控制台 | 节点拓扑/任务看板/模板市场/用量统计 | 静态托管 |

### 边缘代理（dsh-edge 插件）
四件事（刻意薄，免疫 DSH breaking changes）：①注册（中控地址+node token）②心跳 60s（在线/当前任务/资源水位）③执行（拉任务→调本机 dsh CLI/API→流式回报→终态回传，产出默认留本机）④用量上报（token/时长）。安装：`dsh plugin install dsh-edge` → 填中控地址入网。

### 模型网关（中控内置）
/v1/chat/completions、/v1/models、/v1/embeddings；供应商抽象（DeepSeek/通义/Claude/Ollama）；v0.1 按模型名直路由+按 node token 配额；计量落库（谁/任务/模型/token/估费）。

## ADR-004 知识层：轻量本体（Palantir 启发，H7）

- **对象/属性/链接**三件套作 schema 语言；**动作类型**一等公民（参数 schema+提交校验 submission criteria+副作用清单+执行日志+可撤销）
- **Staged writes**：AI 产出默认暂存→人审→原子落库；成熟动作逐级放行
- **本体 MCP 化**：对象/动作自动暴露为 agent 工具（参考 ObjectStack `ai:{exposed:true}`）
- **struct 模式**存 AI 产出元数据：{值,来源,置信度,时间}
- **不抄**：数据集成深度/多继承接口/Global Branching 全量/自研存储引擎

## ADR-005 领域模板标准：四段式

①对象模型（实体+属性+关系）②动作库（参数+校验+副作用）③工作流（编排动作与 AI 步骤，引用①②）④评测集（模板自带测试=市场质量徽章）。分发物=可运行的领域微缩本体。

## ADR-006 动作自主性分级（Palantir staged writes × DMLA L1-L5 × 检查点哲学的交汇）

每个动作声明自主性等级：**读操作高自主直通（L4）；写操作默认 staged 人审（L2）；成熟后逐级放行（需连续 N 次 A/B 通过）**。约束解码管格式、事后校验管语义（DMLA）。幂等键+补偿事务保障副作用可中和（action reverts 的开源平替）。

## ADR-007 对话学习：企业适配层获取机制

接入企微/飞书/钉钉 → AI 观察对话流提炼高频工作模式 → 生成工作流候选（进 staged writes 人审）→ 确认后上架。边界（H4 验证）：预期承载协同层，领域深层知识仍走专家线。

## ADR-008 产品形态原则

- **钉子不做锤子商店**：嵌入现有流程（IM/DevOps 链/工单），不造新后台
- **解放非替代**：员工助手定位
- **模板提示词分区**：稳定前缀（角色/规则固定段，提高前缀缓存命中）+ 可变段（DMLA #10 成本约束）
- **可胜利区间**：中等关键度、知识密集型工作流（QA/审核/知识管理/流程自动化/内容生产）
- **进化环硬规则**：资产迭代必须 A/B 对比+人审，AI 提议人拍板
- **运行层工程规范**（DMLA 容错五件套）：梯度超时（工具 30s/推理 5min/任务 1h）、指数退避+抖动、降级兜底（附上下文交人工）、检查点、断路器

## ADR-011 部署形态：双模式 + 开源插件生态（2026-09-09 用户决策）

**同一产品、两种部署形态**：

| 形态 | 目标用户 | 组成 | 呈现 |
|------|----------|------|------|
| **单机模式（all-in-one）** | 个人用户/轻量场景 | 一个本地进程打包全部：本体层+模板库+内置执行器+Web 控制台 | localhost Web 控制台（未来可桌面壳，参考 dsh-desktop 先例）；数据全本地 |
| **企业模式（server+edge）** | 2B 企业级 | 服务器中控 + 各办公电脑边缘代理（dsh-edge） | 服务器 Web 控制台（管理员）+ IM 嵌入（成员）+ MCP（agent 用户） |

**架构约束**：
- 中控必须是**模块化单体**：所有组件（本体/模板/编排/网关/控制台）可在单进程内组装——单机模式=同一代码库的 all-in-one 打包，不是分叉产品
- 单机模式下边缘代理概念退化为**内置本地执行器**（跳过注册/心跳，直接进程内调用）
- 配置驱动形态切换：`--mode standalone|server|edge`，一套代码三种运行身份

**开源与插件生态**：
- 项目开源（强保护协议，ADR-009），支持**第三方插件**：领域模板包（四段式）为主要扩展形态；动作类型 DSL 预留第三方连接器扩展点（custom action provider 接口）
- 模板包规范即插件规范：第三方按四段式 DSL 开发模板+evals，经硬化清单可入市场
- 个人单机模式与对话学习天然契合（个人聊天记录导入学习），与 distilly 验证的个人场景呼应


## ADR-012 呈现形式：多形态 HMI，IM 仅辅助（2026-09-09 用户纠偏）

**呈现形式的本质是人机交互层，不是 IM 通道**（纠正此前"IM 嵌入"被过度前置的倾向）。

| 层 | 形态 | 定位 |
|----|------|------|
| **主 HMI（人机交互）** | ①本地网页（单机模式默认）②**CLI**（开发者第一界面，API 薄壳）③VS Code 插件（编辑器内）④桌面终端应用（v0.2+，学 dsh-desktop 先例） | 个人与企业模式共用这组形态，全本地可打开 |
| **辅助通道** | IM（通知/审批卡片等轻操作） | 通知抵达层，不是工作界面；企业模式后续按需加 |
| **agent 界面** | MCP | 外部 agent（Claude Code/DSH）直连本体 |

- 与执行底座（DSH 终端 harness 生态）的界面习惯同构：CLI/编辑器/桌面是 harness 用户已有界面，不发明新形态
- 对话学习中的 IM 是**数据获取机制**（从企业 IM 学习惯），与呈现层无关——两件事不再混谈
- v0.1 呈现：本地 Web 控制台 + **CLI（`yuanzhu` 命令：本体查询/模板操作/审批/任务触发）**；VS Code 插件与桌面壳留 v0.2+


## ADR-013 元流程载体演进：md 规格 → 代码机制（2026-09-09 用户洞察）

**md 是规格不是控制**——提示词级约束靠自觉，无强制力/无状态/无审计。平台化的本质 = 把 md 里靠自觉的纪律变成代码里不可绕过的机制：

| 元流程 v2 条款 | md 阶段（现在） | 代码阶段（v0.1+） |
|---------------|----------------|-------------------|
| staged 人审 | 检查点纪律（自觉） | action_exec 状态机（DB，绕不过） |
| 硬化三件门 | 交付清单（自觉） | CI 发布硬门禁（缺一拦截） |
| 知识环两问 | 交付时提问（自觉） | 本体层规则对象+提炼 job |
| 软遗忘 | 标注（自觉） | 权重衰减（数据结构） |
| 自主性分级 | 方案标注（自觉） | action_type.autonomy_level 字段强制 |
| 审计 | 报告里写（自觉） | 操作日志自动落库 |

演进顺序 = 平台开发优先级的又一依据：本体层/staged writes 第一（最要紧的控制先代码化）。

## ADR-014 模型网关多协议 Provider 注册表（2026-09-10 用户指示：dsh 的 key 要兼容复用）

**需求**：用户用起来才方便——dsh 已配好的模型 key 不应要求在元铸工坊再配一遍；且要支持多种协议接入任意供应商。

**决策**：网关经 **ProviderRegistry 三层配置源**路由模型（先到先得）：

| 层 | 来源 | 形态 |
|----|------|------|
| ① dsh 导入（零配置） | `~/.dsh/settings.yaml` 的 `llm-pi-ai.providers` + `.credentials.yaml` refs 解 key | dsh 用户开箱即用 |
| ② .env 自定义 | `YUANZHU_PROVIDER_n_{NAME,BASE_URL,API,KEY,MODELS}` 四件套+模型清单 | 任意 OpenAI 兼容端点（vLLM/Ollama/one-api/自建中转） |
| ③ 内置兜底 | 裸模型名 → litellm 原生前缀（deepseek 等） | 环境变量凭据，litellm 约定 |

**协议映射**（与 dsh 的 `api` 字段语义对齐）：
- `openai-completions` → litellm `openai/<model>` + `api_base` + `api_key`（覆盖一切 OpenAI 兼容端点）
- `anthropic-messages` → litellm `anthropic/<model>`（预留）

**路由规则**：模型名精确查注册表（dsh/自定义命中优先）→ 内置映射 → litellm 原生带前缀名放行；全未知则报错并列出全部可用模型（排错友好）。

**实证（2026-09-10）**：dsh 天翼云 key 零配置导入 58 个模型；glm-5.1/5.2 真实对话；AIQA 报告工作流全真跑通（真实 Bug → GLM 分析 → Report staged → 计量落库 1758 tokens）。

**影响**：v0.1 的「用户提供模型 key」待办就此消灭；后续新增供应商只需配 provider，不改代码。
