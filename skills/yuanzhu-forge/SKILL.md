# 一句话铸工作流（Forge）

用户描述了一件重复性的工作 → 用元铸工坊把它铸成四段式模板（对象模型+动作库+工作流+评测集）。

## 前置检查

先确认元铸工坊服务在跑（MCP 工具能调通）。调不通就告诉用户：

> 元铸工坊服务未启动。请先运行 `yuanzhu-server`（安装：`pip install yuanzhu`），服务默认在 http://127.0.0.1:8600

## 步骤

1. **把用户的话整理成一句工作描述**：谁 + 做什么 + 产出什么。例："我每周五要收集各小组进展，汇总成一份周报发给领导"。
   - 用户说得零散就帮他归纳，**归纳后念给用户确认再铸造**（铸造要走 AI 生成+评测，别浪费在理解偏差上）。

2. **铸造**：调 MCP 工具或在服务端执行 `POST /api/templates/forge`，body 为 `{"description": "<整理后的描述>"}`。铸造耗时约 30-60 秒（AI 生成 + 冒烟评测）。

3. **解读结果给用户**：
   - `status: "published"`：评测全过已上架。告诉用户去模板市场（Web http://127.0.0.1:8600）或用 `/yuanzhu` 命令查看使用。
   - `status: "draft"`：评测没全过，留在草稿。把 `evals.failures` 念给用户，说明差在哪（通常是数据流或字段约束），可去 Web 模板市场修正后重跑。
   - 两种结果都要展示 evals 通过情况（几个用例、全过与否）。

## 边界

- 描述太短（<6 字）服务端会拒绝——引导用户说清楚。
- 铸造是**写操作但已内置三道守门**（dry-run 结构校验 / 工作流冒烟 / evals），直接执行没问题。
- 不要替用户编造业务细节——描述里没有的字段留空让服务端校验兜底。
